# Decisions

Each decision gives what was decided and where the reasoning is. A later decision that replaces one says so, and the old entry is marked replaced rather than deleted. Status and open questions are in [README.md](README.md).

1. **Stop testing models for this kind of call** (2026-10-24). Whisper Large v3 with Chinese forced plus Sortformer was good enough on a three-person online Chinese + English call. See [both full recordings](experiments/2026-10-24-full-recordings.md).
2. **Pipeline candidate** (2026-10-24): Whisper Large v3 (Chinese forced) or Breeze-ASR-25, Sortformer, labels attached by overlap per word, a naming step that can merge labels, Traditional script output. See [experiments](experiments/README.md).
3. **Summaries and the other catalogue features are separate questions** (2026-10-24).
4. **Experiments run through the `meeting-experiment-review` skill** (2026-10-29): private dataset outside Git (`$MEETING_REVIEW_DATA`), a public summary in `docs/experiments/` committed before the first run, and a code snapshot per experiment so the live scripts carry no options kept only for old experiments.
5. **Repository layout** (2026-10-29, [#8](https://github.com/pomodorozhong/meeting-recap/issues/8)):
   - `experiments/<name>/` holds one self-contained experiment each: its code, pinned dependencies, and a README or summary link saying how to run it. Nothing outside the folder imports from it, and it never holds private data.
   - `experiments/pipelines/<name>/` holds candidate pipelines for saved recordings, under the same rules. Several can coexist while they are compared.
   - `app/` is the root of the final app. Once one pipeline is settled, the app gets its own copy of it, rebuilt as the app's code and dependencies; it does not depend on anything in `experiments/`. The experiment stays as the record its summary cites.
   - Decisions go in this file, one numbered entry each, rather than one file per decision: the project is small, and a single list is easier to read and keep current.
6. **A two-person, two-track call is its own speaker reference** (2026-10-30). When a real call is recorded with [`experiments/capture/`](../experiments/capture/), has exactly two speakers, and the local speaker wore headphones, `mic.m4a` holds Speaker A and `system.m4a` holds Speaker B, so voice activity on each track gives who speaks when across the whole call without a listening session. This narrows the rule that a reference from known turns is for generated audio only: it now also covers these calls, and nothing else. Overlapping speech and short sounds such as laughs and backchannels are where track activity is least certain, so a few listened clips there check it. A call with more than one remote speaker still needs listening to split the system track. A meeting app's own speaker labels are not a reference; they can be wrong about how many people spoke.
7. **First saved-recording pipeline and its recap model** (2026-11-01, [#28](https://github.com/pomodorozhong/meeting-recap/issues/28)). [`experiments/pipelines/whisper-sortformer/`](../experiments/pipelines/whisper-sortformer/README.md) assembles decision 2's baseline end to end. Whisper Large v3 runs through MLX rather than the WhisperKit CLI: same weights, already pinned in the runner guide, and no separate binary. The recap uses Qwen3.5 9B 4-bit through `mlx-lm` (`mlx-community/Qwen3.5-9B-4bit` at `8b2b98c00a6b4d291155e4890773ca8f769aee53`), pinned by Hugging Face revision like the other models. About 6.7 GB at peak, one model loaded at a time. Local language models run through MLX only, not Ollama. If the MLX route breaks, the blocker is raised for a decision rather than switching runtimes. Fixes to the pipeline follow the ranked issues from its synthetic baseline and the private-recording review, not component scores alone.

8. **F5 female voice for the synthetic fixture collection** (2026-11-02, [#4](https://github.com/pomodorozhong/meeting-recap/issues/4)). The collection uses `f5-news-female` with the exact published reference WAV and pinned F5 v1 4-bit model and Vocos files described in [the synthetic-call voice configuration](../experiments/synthetic-call/reference/f5-voice.json). Qwen CustomVoice supplies the male presets. Each F5 turn records an explicit duration, and the script seed is reset for each female turn. The fixed three-turn Whisper gate requires both embedded English tokens in their expected turns and a repeatable WAV. Replacing a voice regenerates the affected audio, transcript times, speaker intervals and hashes together. The original F5 pretrained weights carry CC-BY-NC-4.0 terms, and the demo reference archive does not state separate recording redistribution terms.

9. **Female voice diversity in the synthetic collection** (2026-11-02, [#4](https://github.com/pomodorozhong/meeting-recap/issues/4)). This extends decision 8 with EmotiVoice factory presets 1093, 1012 and 1066 in a separate three-speaker localization call. The localization call is part of the hash-verified collection. EmotiVoice runs in its own locked CPU project with Torch 2.10.0 and Transformers 4.57.6 to match the runtime these presets were auditioned with; those auditions are kept outside this repository. Its source, synthesis weights, SimBERT encoder, NLTK data and dependency artifacts are pinned. The main generator batches those turns before loading GPU speech models. See [the voice configuration](../experiments/synthetic-call/emotivoice/pins.json).

10. **English coverage and separate language regression scores** (2026-11-02, [#4](https://github.com/pomodorozhong/meeting-recap/issues/4)). The synthetic collection includes six English scripts with 2,947 words across one through four speakers and five voice profiles. Tests enforce minimum English volume and explicit English routing. Benchmark transcript reports show English WER and Mandarin CER separately, with no pooled score. A baseline comparison fails when either language regresses, even if the other improves, and requires all scripted calls. English scripts declare `language: en`; the other scripts use the Mandarin default. See [the coverage and scoring commands](../experiments/synthetic-call/README.md#english-coverage-and-transcript-regression-checks).

11. **Every experiment has one entry point** (2026-11-03). An experiment's folder has one script that runs everything up to any step only a person can do, then says what that step is. A separate setup script prepares what needs the network. The summary opens with how to run them, what they write, and what differs on a rerun, followed by the question, plan, results and where it ran, as in [the template](experiments/TEMPLATE.md). It is written for someone reading `main`, so anything not on `main` is named as such. A list of commands in prose isn't enough, because a reader can't tell what covers the whole experiment or what was left out. This applies to experiments registered from now on. [#5](https://github.com/pomodorozhong/meeting-recap/issues/5) covers the 2026-10-24 summaries.

12. **Keep conservative defaults and expose the measured alternatives** (2026-11-02). On the [17-recording synthetic collection](experiments/2026-11-02-expanded-pipeline.md), declaring the language helped all six English calls. Keep full Whisper and Sortformer with word-level attachment; use the recording's spoken language. Offer Turbo Q4 for speed, Who when users can check speaker identity, and full Whisper's five-second exact-zero split for digitally edited recordings. Skip recognition and recap on entirely zero audio. Offer separate timestamped lines per ASR segment for finer recap citations: fully supported facts improved on two calls and tied on a third. A correct owner, date or decision still needs checking against the cited speech. No change to the recap model or prompt, and no automatic rejection of action items based on the tested verifier.
